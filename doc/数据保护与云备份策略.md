## 一、数据存储架构

### 1.1 本地存储（localStorage）

| 键名 | 用途 | 格式 |
|------|------|------|
| `asset_ledger_logs_v4` | 收支流水记录 | JSON 数组 |
| `asset_input_cache_v4` | 资产概览输入缓存 | JSON 对象 |
| `asset_snapshots_v4` | 本地快照（日期→数据） | JSON 对象 |
| `asset_view_mode_v4` | 账目流水视图模式 | 字符串 |

## 二、云备份策略（Supabase）

### 2.1 配置信息

| 配置项 | 值 |
|--------|-----|
| Supabase URL | `https://mqdxmbsaddebxlallgos.supabase.co` |
| 数据表 | `asset_ledger_snapshots` |
| 认证方式 | 邮箱 + 密码 |

### 2.2 数据表结构

```sql
CREATE TABLE asset_ledger_snapshots (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL,
  week_label TEXT NOT NULL,
  snapshot_type TEXT NOT NULL,  -- 'auto' | 'manual'
  data JSONB NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2.3 同步机制

#### 自动同步
- **触发条件**：用户登录后自动触发
- **频率**：每周一次（基于 ISO 周标签 `YYYY-Wnn`）
- **逻辑**：检查本周是否已有备份，无则创建

#### 手动同步
- **触发方式**：设置菜单 → ☁️ 同步云端
- **标签格式**：`YYYY-MM-DD_HH:mm`
- **用途**：重要操作前的手动备份

### 2.4 恢复流程

1. 设置菜单 → 📋 云端历史
2. 查看备份列表（最多50条，按时间倒序）
3. 点击「🔄 恢复此备份」
4. 确认后覆盖当前数据

## 三、本地导出/导入

### 3.1 导出

- **入口**：设置菜单 → 💾 导出数据
- **文件名**：`资产账本备份_YYYY-MM-DD.json`
- **内容**：assets + logs + snapshots 完整数据

### 3.2 导入

- **入口**：设置菜单 → 📂 导入数据
- **兼容格式**：
  - 标准导出格式
  - 分类备份格式（含 `_categorized` 后缀）
  - 自动检测同目录备份文件（需 HTTP 服务）

### 3.3 自动加载

页面首次打开时，若 localStorage 无数据：
1. 尝试 fetch 同目录下的 `资产账本备份_*.json`
2. 失败则提示用户手动导入

## 四、数据保护措施

### 4.1 清空数据保护

清空操作需要多重确认：
1. 确认是否已导出数据
2. 输入用户名/密码二次确认
3. 最终确认清空

### 4.2 .gitignore 保护

以下文件不提交到 Git：

```
# 隐私数据备份
资产账本备份_*.json

# Python 脚本
*.py

# Excel 数据
*.xlsx

# Excel 临时文件
~$*

# 其他目录
无主流程/
```

### 4.3 本地测试服务器

- 启动：`python -m http.server 8080`
- 用途：访问 `http://localhost:8080/my_assets_v4.html`
- 关闭：`Stop-Process -Name python* -Force`

## 六、安全注意事项

1. **Anon Key**：Supabase anon key 已嵌入代码，仅限公开表操作
2. **数据加密**：本地和云端均使用明文 JSON 存储
3. **访问控制**：云备份通过 Supabase Auth 用户隔离
4. **建议**：定期导出本地备份，重要操作前手动云同步
